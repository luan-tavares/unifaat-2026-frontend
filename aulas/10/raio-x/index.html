Etapa 1 · RabbitMQ: exchange

RabbitMQ: exchange fanout (assertExchange, notify, subscribe)

Jobs de um lado (fila + workers), notificações do outro (exchange + consumidores, cada um com a sua fila dinâmica). As três funções recebem o nome do exchange por parâmetro.

src/database/connections/rabbit.js (acrescentar no módulo e no return)
+ const assertExchange = async (exchange, type = 'fanout', options = { durable: false }) => {
+ const ch = await createChannel()
+ await ch.assertExchange(exchange, type, options)
+ return ch
+ }
+
+ // producer: publica no exchange; quem entrega é o fanout
+ const notify = async (exchange, event, payload) => {
+ const ch = await assertExchange(exchange)
+ const message = Buffer.from(JSON.stringify({ event, payload }))
+
+ return ch.publish(exchange, '', message)
+ }
+
+ // consumer: fila exclusiva DESTE processo, ligada ao exchange
+ const subscribe = async (exchange, onNotification) => {
+ const ch = await assertExchange(exchange)
+ const { queue } = await ch.assertQueue('', { exclusive: true })
+
+ await ch.bindQueue(queue, exchange, '')
+
+ return ch.consume(queue, (msg) => {
+ if (!msg) {
+ return
+ }
+
+ const { event, payload } = JSON.parse(msg.content.toString())
+
+ onNotification(event, payload)
+ }, { noAck: true })
+ }
...
return {
connect,
createChannel,
assertQueue,
+ assertExchange,
+ notify,
+ subscribe,
publish,
consume,
close
};

O que muda

O exchange vira explícito: toda mensagem já passava por um (o padrão, ""); agora declaramos um fanout com nome. O exchange vai por parâmetro.

Fila dinâmica

O subscribe cria uma fila exclusiva, sem nome, para este processo e a liga ao exchange: N consumidores = N filas no mesmo exchange.

Pegadinha

O rabbit.js guarda UM canal compartilhado; exclusive faz a fila sumir quando o processo cai.

+ import fs from 'node:fs/promises'

+ export default async function loadEvents(eventsPath) {

Etapa 3 · Event (a unidade do websocket)

Event de exemplo: ChatMessageEvent (app/Events)

O Event só chama context.notify (publica no exchange); não faz io.emit. Não conhece o nome do exchange: ele vem preso no notify montado pelo entrypoint. Event novo = arquivo novo em app/Events, sem mexer no entrypoint.

src/app/Events/ChatMessageEvent.js (novo)
+ import { createEvent } from '../../utils/event.js'
+
+ export default createEvent({
+ name: 'chat:message',
+ handle: async (payload, context) => {
+ const { name, text } = payload
+
+ if (!text) {
+ return
+ }
+
+ // não entrega na tela: publica no exchange e TODOS os servidores recebem a cópia
+ await context.notify('chat:message', { name, text, sentAt: Date.now() })
+ }
+ })

Só publica

O Event não faz io.emit: chama context.notify e o exchange distribui para todos os servidores.

Um arquivo por Event

Event novo = arquivo novo em app/Events; o entrypoint não muda, como um Job novo não muda o worker.

Etapa 4 · Entrypoint websocket

Entrypoint websocket: _websocket.js com --exchange e --port

Novo entrypoint ao lado de _web.js, _worker.js e _command.js. Carrega os Events, aceita conexões Socket.IO, registra um socket.on por Event e assina o exchange escolhido para fazer o broadcast (io.emit) aos clients DESTE servidor.

src/_websocket.js (novo)
+ import { Command } from 'commander'
+ import { createServer } from 'node:http'
+ import path from 'node:path'
+ import { fileURLToPath } from 'node:url'
+ import { Server } from 'socket.io'
+ import loadEvents from './utils/loadEvents.js'
+ import rabbit from './database/connections/rabbit.js'
+
+ const __dirname = path.dirname(fileURLToPath(import.meta.url))
+
+ const program = new Command()
+
+ program
+ .name('websocket')
+ .description('Servidor WebSocket (consumer de notificações do RabbitMQ)')
+ .option('--exchange <exchange>', 'Nome do exchange fanout que este servidor assina')
+ .option('--port <port>', 'Porta do servidor WebSocket')
+ .parse(process.argv)
+
+ const options = program.opts()
+ const exchange = options.exchange || 'notifications'
+ const port = Number(options.port || 3001)
+
+ const events = await loadEvents(path.join(__dirname, 'app', 'Events'))
+
+ const httpServer = createServer()
+ const io = new Server(httpServer)
+
+ await rabbit.connect()
+
+ // o Event só enxerga "notify"; o exchange fica preso aqui, na hora de montar
+ const notify = (event, payload) => rabbit.notify(exchange, event, payload)
+
+ io.on('connection', (socket) => {
+ console.log(`Cliente conectado: ${socket.id}`)
+
+ for (const event of Object.values(events)) {
+ socket.on(event.name, (payload) => event.handle(payload, { socket, notify }))
+ }
+
+ socket.on('disconnect', () => console.log(`Cliente saiu: ${socket.id}`))
+ })
+
+ // volta do exchange: cada servidor entrega aos SEUS clients conectados
+ await rabbit.subscribe(exchange, (event, payload) => io.emit(event, payload))
+
+ httpServer.listen(port, () => {
+ console.log(`Websocket iniciado na porta ${port}. Exchange: ${exchange}`)
+ })

Exchange por parâmetro

--exchange e --port, como o worker escolhe a fila com --queue.

O autor também recebe

A volta pelo exchange é o único caminho para a mensagem aparecer na tela, igual para todos.

Etapa 6 · Entrypoint websocket

Etapa 8 · Evento pesado: o worker processa

Evento pesado: o websocket só distribui, o worker processa (upload de imagem)

Regra: o entrypoint websocket só conecta e distribui eventos; nada pesado roda nele (Node tem um event loop só: uma conta pesada congela TODOS os túneis do processo). Websocket e worker são containers diferentes no MESMO RabbitMQ. Exemplo: upload de imagem no chat (o arquivo vai por HTTP para o storage; o Event leva só a referência).

src/app/Events/ChatImageEvent.js (novo)

+ import ProcessChatImageJob from '../Jobs/ProcessChatImageJob.js'
+
+ export default createEvent({
+ name: 'chat:image',
+ handle: async (payload, context) => {
+ const { room, file, author } = payload
+

O websocket só distribui

Conta pesada trava o event loop: todos os túneis do processo congelam. O Event só entrega o trabalho.

Mesmo RabbitMQ

Job na fila images, resultado em outro exchange (results); cada websocket recebe numa fila dinâmica própria.

Pegadinha do dispatch

Hoje fecha a conexão ao terminar: no websocket só pode fechar se foi ele quem abriu.

Etapa 9 · Escala das conexões

Nginx: upstream para distribuir as conexões entre réplicas do websocket

docker/nginx/default.conf.template (substitui o proxy_pass direto da Etapa 07)
+ upstream websocket_servers {
+ ip_hash; # sticky (só importa no polling do Socket.IO)
+ server nodewebsocket_host:3001; # o Docker devolve o IP de cada réplica
+ }
+
location /socket.io/ {
- proxy_pass http://nodewebsocket_host:3001;
+ proxy_pass http://websocket_servers;

O nginx também escala

Distribui as conexões entre as réplicas (upstream); a conexão fica presa à réplica escolhida.

Sala de aula

ip_hash põe a turma toda (mesmo IP) numa réplica só: para a demo, client só WebSocket e round-robin.
